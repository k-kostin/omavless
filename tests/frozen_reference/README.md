# Frozen Python behavior references

These are **synthetic test expectations**, not profiles, credentials or live VPN
results. They are generated by the archived Python implementation at immutable
commit `aa5873783c019edc303a732e55ea8c85f1f0b090`, never from Rust output.

The existing Rust differential tests still construct and inspect their inputs
and compare Rust behavior with the independently captured reply. Their tiny
Python launch shims now only replay the matching JSON fixture. No backend import,
network, subprocess or private-store access occurs in ordinary replay. Python
is developer test tooling, not an application dependency.

Each file binds the tool name, exact argument/input hash, byte/argument counts,
reference commit, exit code and stdout/stderr. Raw inputs and argument values
are not duplicated here; the synthetic vectors remain in the Rust tests and
`tests/parity_cases`. A changed or missing vector fails with a fixed safe error;
it cannot silently match a different fixture or invoke the old backend.

## Explicit reproduction

Create a separate clean detached checkout of the fixed reference commit. Never
record private fixtures, opt-in live tests or arbitrary application traffic.
On the candidate checkout, run the ordinary deterministic suites with:

```sh
OMAVLESS_RECORD_REFERENCE=1 OMAVLESS_REFERENCE_CHECKOUT=/absolute/clean/archive cargo test --workspace --locked
```

Use the same environment for the focused Python adapter tests in `tests/run.sh`.
The recorder checks a closed 43-tool allowlist, archive commit/cleanliness and exact tracked tool blob,
runs that archived Python tool, and refuses to replace a conflicting fixture.
It does not fetch a moving branch, execute the Rust candidate to derive expected
answers, or accept the live route helper as a frozen oracle. Inspect changes,
then rerun both suites **without** recording variables to verify offline replay.

Adding a new Rust feature is not permission to grow the archived Python backend.
Use ordinary Rust tests for its explicitly reviewed contract. Intentional changes
to an existing historical contract need a documented expectation amendment;
never turn a failing parity assertion into success by automatically recording
the candidate's own result. Historical Python-only implementation and its old
tests remain recoverable from `archive/python-legacy`.

Installed-core/live gates must exercise the actual Rust implementation. Removing
their historical Python comparison does not turn them into replayed PASS claims.
Coverage and the retirement gate are recorded in `docs/roadmap/LEGACY_RETIREMENT.md`.

The separate `tests/parity_cases/support-policy-counts-v1.json` records the old
inline oracle from `support_diagnostics.rs`: for each of its six inputs, call
the archived backend's `yaml_sequence_count(yaml_top_level_block(text, "rules"))`
and `yaml_mapping_count(yaml_top_level_block(text, "rule-providers"))`. Store the
two counts with the exact input SHA-256 and pinned reference commit. This is
also independent Python behavior, not a count computed by the Rust candidate.
