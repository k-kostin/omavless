## Before-decision evidence, not error handling

For each initial/final bus/resolved pass, finite before-effect labels distinguish
live anchor, child binding, maps read, strict grammar parse, membership/target
verification, maps reread/reparse and final live-anchor check. No label is emitted
after its preceding prerequisite fails. The original 128 breadcrumb limit stays
unchanged; the fixed successful invocation uses at most 101 such labels.

Only each daemon's **initial** pass may additionally emit a public candidate
record, immediately after strict map grammar and before that candidate's
membership/device-inode check or target open/hash. The record has fixed schema
`public-map-candidate-before-admission-v1`, fixed daemon/pass, canonical public
`/usr/lib/` or `/usr/bin/` pathname, integer mapped device/inode, and literal
`identity_proven=false`, `adoption=false`. Each daemon permits at most 64 records;
the combined serialized record budget is at most 1 MiB. Unknown/private/deleted/
noncanonical path grammar, booleans, invalid integer ranges, overflow and short
or unknown stderr write permanently refuse. There is no retry or second write.

These records describe already-read map text only. They do not prove the named
object, authorize opening an unknown object or expand any copy table. The source
does not catch a failed admission in order to emit a diagnostic: the candidate
record precedes the decision, and the first failure still parks PID1 silently.
Final and shutdown passes never emit candidate records. Existing target-open,
original FD checks and exact map device/inode matching are not relaxed.

The outer observer still stops without later queries on unknown/nonzero/deadline.
An unresolved namespace remains unresolved; no automatic signal/reap/cleanup,
archive or log extraction follows. Any later file diagnosis needs a separately
reviewed scope and must accommodate the new bounded candidate stream without
mistaking a record for loaded identity or success.
