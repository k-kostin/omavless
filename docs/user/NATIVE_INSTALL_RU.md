# Руководство пользователя OmaVLESS

> Черновик для предлагаемого snapshot **0.9.9**. Для опубликованной версии
> используйте [действующее руководство main](https://github.com/k-kostin/omavless/blob/main/docs/user/NATIVE_INSTALL.md).

<a id="set-up-update-or-reopen-omavless"></a>

Это руководство для **OmaVLESS 0.9.9 в Omarchy**. Установка и запуск
приложения не подключают VPN. Импортируйте собственный поддерживаемый профиль
и отдельно выберите подключение; серверы и подписки в приложение не входят.

Виджет — это значок в панели и открываемая им панель управления. Пакет
`omavless` содержит native-приложение и терминальный интерфейс. Пакет
`omavless-dns` содержит согласованные с ним ядро Mihomo и DNS-помощник.
Помощник управляет разрешением адресов сайтов для соединений OmaVLESS;
обычное отключение убирает только DNS-настройки OmaVLESS. Отдельно установленный
Mihomo остаётся без изменений. Выбор DNS-провайдера — отдельная настройка.

Перед первоначальной настройкой отключите другие VPN-соединения. OmaVLESS
не отключает их за вас и не настраивает совместную работу автоматически.

первоначальную настройку без импорта. Ни одно из этих действий не запускает VPN.

## Первоначальная настройка

1. Добавьте виджет средствами Omarchy:

   ```sh
   omarchy plugin add https://github.com/k-kostin/omavless.git --enable
   ```

   Это добавляет виджет, но не native-приложение и не ядро VPN. Команда
   не запускает отдельный `install.sh` и не запрашивает права администратора.
2. Откройте OmaVLESS из панели и выберите **Установить необходимые компоненты**.
   В терминале введите `INSTALL`. Проверьте обычную пакетную транзакцию;
   пароль вводите только в системном запросе пароля.
3. Введите `DNS`, когда будет запрошено разрешение помощнику для указанной
   учётной записи. Этот отдельный административный шаг запускает помощник
   сейчас и при загрузке компьютера. Автоподключение VPN он не включает.
4. Когда терминал сообщит о готовности, завершите системные запросы и закройте
   его. Если показано, выберите **Терминал и запросы системы закрыты**, затем
   **Проверить снова**. При отмене более позднего шага используйте оставшееся
   предложенное действие, а не начинайте установку заново.
5. Завершите первоначальную настройку: проверьте готовность, при необходимости
   выберите маршрутизацию и импортируйте профиль либо выберите
   **Завершить без профиля**. На экране готовности ядра нажмите **Продолжить**.
   Готовность не является проверкой соединения. Новая установка включает запуск
   приложения при будущих входах, а автоподключение VPN по умолчанию выключено.
   После завершения дождитесь главной панели. Само завершение не запускает VPN.

Если предложены разделы установки компонентов, их настройки и обновлений,
они ведут к соответствующему следующему действию. **Проверить состояние**
только проверяет; пакеты не устанавливаются и не обновляются. Для обычной
установки не нужны отдельный Mihomo, ручной `setcap`, Python или Rust toolchain.

<a id="connect-and-disconnect"></a>

## Подключение и отключение

Импортируйте поддерживаемую ссылку профиля, файл профиля или HTTPS-подписку
через буфер обмена либо файловые кнопки. Проверьте импорт перед сохранением.
Поддержка конфигураций WireGuard и AmneziaWG экспериментальная и ограничена
подмножеством из раздела [Поддерживаемые профили](PROTOCOLS.md). Произвольный
Clash/Mihomo YAML не принимается. Ссылки, конфигурации и адреса подписок могут
давать доступ к VPN; храните их приватно.

Экспериментальное подключение WG/AWG поддерживает одного peer, IPv4,
стандартный WireGuard и поддерживаемую форму конфигурации AWG3, включая
импортированные IPv4 DNS. Импорт и экспорт dual-stack данных не включают IPv6
подключение. Переменные диапазоны keepalive и неподдерживаемые параметры AWG
приводят к отказу подключения; скалярный ноль явно выключает persistent
keepalive. Несколько peer и исполняемые директивы `.conf` отвергаются.
Общей гарантии для других поколений AWG нет. Успешный импорт не проверяет
совместимость с сервером.

Для подключения и смены сервера нажимайте **Подключить рядом с нужным профилем**.
Нажатие на имя выбирает профиль для панели действий, но не подключает его.
Фильтрация списка не отключает скрытый профиль. Подключённый профиль также
указан над элементами управления.

Главный переключатель включает и выключает соединение; это не выбор сервера.
При установленном соединении он отключит его, даже если выбран другой профиль.
Перед следующим действием подключения или смены режима дождитесь подтверждённого
завершения и закончите либо отмените связанный системный запрос.

| Режим | Значение |
| --- | --- |
| **Полный VPN** | Использует подключённый VPN-профиль для политики полного VPN. |
| **Маршрутизация** | Выбирает VPN или прямой доступ по вашему пресету маршрутизации и правилам доменов/IP. |
| **Напрямую** | Обходит прокси, сохраняя туннель. Это не отключение. |

Состояние «Подключено», готовность и счётчики не доказывают доступность
каждого сайта или прохождение всех потоков через VPN. После подключения
проверьте фактический доступ к сайтам.

<a id="profiles-and-subscriptions"></a>

### Профили и подписки

Разверните подписку стрелкой. **↻** рядом с количеством серверов означает
**Обновить список серверов**, а не проверку задержки или переподключение.
**Обновить всё** обновляет все источники. Дождитесь завершения; ошибка загрузки
не означает сохранения нового списка. Удаление подписки также удаляет её
управляемые профили — это указано в подтверждении.

Избранное, переименование, редактирование, QR, экспорт, сведения и удаление
относятся к профилю, названному в панели действий. Для профилей подписки
сохраняются ограничения редактирования. Экспорт и QR содержат приватный доступ
к VPN; не публикуйте их.

Фильтр протоколов появляется, если в ваших профилях больше одного протокола.
Он предлагает протоколы из вашего списка. Изменение фильтра или поиска
не меняет соединение и выбранную цель действий.

По умолчанию подписки обновляются вручную. Через локальный CLI доступно
добровольно включаемое расписание Daily (`omavless --help` перечисляет
`subscription schedule`). Оно обновляет списки серверов без подключения VPN.
Пропущенные дни не воспроизводятся серией запросов. Перед изменением расписания
текущее обновление должно завершиться или быть явно отменено; потерянный ответ
не разрешает отправлять действие заново.

<a id="routing-and-dns"></a>

### Маршрутизация и DNS

В настройках доступны поддерживаемые пресеты маршрутизации и пользовательские
правила. Проверяйте и сохраняйте их предложенными элементами управления;
отклонённое или неподтверждённое сохранение не является применённым изменением.
Произвольный редактор шаблона маршрутизации/YAML не предлагается.

При отключённом VPN для DNS доступны **По умолчанию**, **Google** и
**Cloudflare**. Сохранение применяется при следующем явном подключении; оно
не подключает и не перезагружает текущее соединение. Вариант «По умолчанию» использует
DNS пресета маршрутизации. Пользовательская конфигурация или WireGuard сохраняет
собственный DNS; учитывайте объяснение режима только для чтения вместо ожидания,
что пресет его переопределит.

<a id="test-ping-and-diagnostics"></a>

### Тест, Ping и диагностика

Главная панель предлагает явный HTTPS-тест и ограниченное измерение Ping.
Это разные проверки. Учитывайте показанный результат и его возраст;
недоступность или тайм-аут сами по себе не определяют ошибочный ключ,
провайдера или VPN.

Терминальные проверки профилей/подписок измеряют задержку HTTPS, а не ICMP,
общесистемный DNS или утечки. Пакетные задания показывают прогресс и принимают
отмену; дождитесь подтверждённого результата. Режимы «Маршрутизация» и «Напрямую» могут
отправлять проверку напрямую. Соединения, активность, краткая история, маршруты
и ограниченные диагностические подсказки показывают наблюдения, а не полную
защиту или постоянные сырые логи. На странице «Соединения» доступен только
просмотр; управления закрытием соединений в ней нет.

<a id="recorded-traffic"></a>

### Учтённый трафик

Настройки и терминальная страница «Трафик» показывают **Учтённый трафик**:
один локальный период принятых/отправленных байтов, по умолчанию учёт выключен.
Включайте его только при отключённом VPN. Затем учёт продолжается независимо
от открытых окон панели и терминала.

Это байты туннеля приложения, включая режим «Напрямую». Они отличаются от лимита
провайдера, тарификации и доказательства доставки. **Часть трафика могла
не попасть в учёт** отмечает неполный интервал. Приложение не заполняет
ненаблюдаемый интервал выдуманными значениями.

Сохранённые итоги переживают обычный перезапуск приложения. Выключение учёта
сохраняет итоги; **Обнулить трафик…** безвозвратно удаляет предыдущий период
после явного подтверждения. Включение, выключение и обнуление требуют
подтверждённого отключённого состояния и никогда не подключают VPN.
При неподтверждённом результате сначала используйте **Проверить значения**,
а затем решайте вопрос о новом изменении. Статистика локальна для компьютера
и не переносится с резервными копиями профилей, не восстанавливается из них
и не включается в отчёты поддержки.

<a id="open-the-terminal-application"></a>

### Открыть терминальное приложение

Нажмите **Открыть приложение** под панелью действий профиля. Откроется более
просторный терминальный клиент того же приложения либо получит фокус уже
открытое окно. Второй VPN и выключенный вами runtime не запускаются.
При наличии предложения сначала выберите **Запустить OmaVLESS**.

Tab / Shift+Tab меняют страницы; `?` показывает помощь, `,` открывает настройки
сеанса. На странице «Профили» стрелки выбирают строку, `c` подключает, `d` отключает,
а `1` / `2` / `3` выбирают режимы «Полный VPN», «Маршрутизация» или «Напрямую». Сетевые действия
требуют отдельного Enter; Escape отменяет. `t` проверяет выбранный профиль,
`T` — все доступные профили. На странице «Подписки» `n` / `p` выбирают источник,
`s` обновляет его, `S` — все источники; `r` только перечитывает локальное
представление. На странице проверок и обновлений `x` запрашивает отмену.
Выход через `q` и закрытие окна оставляют VPN и принятые фоновые задания
работающими.

`u` на странице «Подписки» запрашивает сообщаемые провайдером трафик и срок действия.
Это приватное утверждение провайдера, а не измеренный трафик туннеля или
проверенное право доступа. При выходе со страницы результат удаляется;
в обычных диагностических отчётах он не сохраняется.

<a id="encrypted-backup-098-candidate"></a>

<a id="encrypted-backup"></a>

### Зашифрованная резервная копия

В настройках терминального сеанса выберите «Копия» (Backup) либо нажмите `b` / F2.
Укажите новое абсолютное имя файла в существующей собственной приватной
папке с правами `0700`. Дважды введите парольную фразу длиной не менее
12 байт. Enter открывает проверку запроса; второй явный Enter создаёт архив.
Escape отменяет действие до отправки. Существующий файл не перезаписывается;
новый файл получает права `0600`.

Резервная копия содержит профили, подписки и поддерживаемый встроенный шаблон
маршрутизации, но не все настройки и состояние ОС. Пользовательский или
неподдерживаемый шаблон может привести к отказу; не сбрасывайте его ради
обхода проверки. Храните архив и парольную фразу безопасно: архив содержит
повторно используемый доступ к VPN, а утраченную фразу восстановить нельзя.

<a id="restore-and-interrupted-operations"></a>

### Восстановление и прерванные операции

В 0.9.8 восстановление из копии отсутствует; для этого раздела нужно соответствующее
приложение 0.9.9.

В настройках терминала `R` открывает «Восстановить» (Restore), когда действие доступно. Выберите
приватный архив и введите парольную фразу. Сначала проверьте аутентифицированный
предпросмотр; отдельное подтверждение заменяет показанные профили/подписки
и шаблон маршрутизации. Восстановление не возвращает все настройки приложения
и состояние операционной системы.

Нужно свежее подтверждённое отключённое и свободное состояние приложения.
При активном соединении предложенное отключение имеет своё подтверждение.
После его завершения дождитесь свежего отключённого состояния и откройте
восстановление из копии заново. Автоматической последовательности «отключить и восстановить» нет.

До отправки Escape отменяет запрос. После отправки дождитесь исходного
результата: закрытие экрана не является отменой. Неизвестный результат
не означает отсутствие эффекта. Сохраните архив и существующее состояние,
следуйте предложенным указаниям восстановления и обратитесь за помощью,
если безопасное продолжение недоступно. Не повторяйте запрос восстановления, не удаляйте
его записи и не сбрасывайте store ради продолжения.
Неподдерживаемое, повреждённое или неоднозначное состояние может оставаться
заблокированным; восстановление из копии не является универсальным ремонтом и не обещает
восстановление после любого сбоя питания или файловой системы.

<a id="preserve-an-incompatible-original-store"></a>

### Сохранить несовместимый исходный store

Несовместимая сохранённая запись может мешать запуску приложения, обычному
экспорту профилей и созданию зашифрованной резервной копии. При установленном соответствующем
приложении 0.9.9 команда `omavless store-compatibility` возвращает безопасную
классификацию без подключения. Код выхода ноль означает получение отчёта;
проверяйте его поле `compatible`.

`omavless store-preserve-original` сохраняет точные байты всего исходного
`profiles.json` до запуска runtime. Копия **не зашифрована и содержит доступ
к VPN**. Это не зашифрованная резервная копия и не исправление; неподдерживаемые
профили остаются неподдерживаемыми.

Выберите существующую собственную приватную папку за пределами управляемых
каталогов конфигурации, состояния и runtime приложения. Используйте новое
имя файла. Выполните команду ниже, затем введите абсолютное имя назначения
в скрытом запросе. Назначение передаётся через stdin, не попадая в аргументы
процесса или историю shell. Это явное подтверждение создания незашифрованной
копии, содержащей доступ к VPN:

```sh
bash -c '
  set -o pipefail
  IFS= read -r -s -n 4097 -p "Private destination for an unencrypted VPN-access copy: " ov_original_destination || exit 2
  printf "\n"
  [[ -n "$ov_original_destination" ]] || exit 2
  printf "%s" "$ov_original_destination" |
    jq -Rs "{destination: ., confirmUnencrypted: true}" |
    omavless store-preserve-original
'
```

Родительская папка назначения уже должна быть приватной (`0700`);
новая копия получает `0600`. Не вставляйте её содержимое или ввод в общие отчёты.
Исходный файл, настройки и соединение остаются без изменений. Небезопасный,
слишком большой, меняющийся источник либо незавершённое состояние приводят
к отказу; команда не ослабляет права, не снимает блокировки и не разрешает
подключение. Существующий файл назначения не перезаписывается. Код выхода 73
или потерянный вывод означают, что копия могла появиться: проверьте её приватно;
не повторяйте команду и не удаляйте возможную копию автоматически.

<a id="continue-dns-setup"></a>

<a id="set-up-dns-helper"></a>

## Настроить DNS-помощник

Если пакеты установлены, а настройка DNS не завершена, выберите
**Настроить DNS-помощник**. Действие доступно только при необходимом
остановленном и проверенном состоянии; неизвестное состояние не считается
новой установкой.

Терминал предлагает отдельные варианты:

- `FIRST`: доступ помощнику для вашей учётной записи ещё не был разрешён.
  Подтвердите отдельный административный шаг при запросе.
- `START`: настройка помощника уже успешно выполнена для этой учётной записи
  на этом компьютере. Используйте существующее разрешение без повторной
  выдачи доступа; введите `SELECT` при запросе.

Enter отменяет. Не выбирайте FIRST из-за отказа START: ошибка не доказывает,
что доступ никогда не настраивался. При сомнениях
[проверьте, что завершилось](#when-setup-stops).

После завершения терминала и системных запросов закройте и подтвердите их,
затем нажмите «Проверить снова». Отдельно выберите **Запустить OmaVLESS**,
когда это будет предложено. Продолжение сохраняет существующие профили
и настройки запуска и не подключает VPN.

<a id="existing-dns-installations"></a>

## Существующие установки DNS

Для существующей выбранной установки следуйте предложенному действию:

- **Запустить DNS-помощник** запускает настроенный помощник после обновления
  или чистой остановки.
- **Другие варианты → Восстановить доступ к помощнику** относится только
  к случаю, когда завершённая чистая переустановка удалила доступ.
  Это не восстановление профилей из копии и не повтор после отказа Start; требуется
  отдельное разрешение DNS.
- `SELECT` выбирает уже установленное и доступное ядро/помощник, если
  остался именно шаг выбора.

Завершите действие и его системные запросы перед запуском OmaVLESS.
Не повторяйте первоначальную выдачу доступа только потому, что помощник
не удалось запустить.

<a id="when-setup-stops"></a>

## Если настройка остановилась

Пакеты могут быть установлены, когда настройка DNS или активация ещё
не завершена. Ввод DNS означает согласие, но не успешное завершение.

1. Завершите или отмените работу терминала и системных запросов. Сам отказ
   не означает, что диалог пароля всё ещё открыт.
2. Сохраните сообщение **Настройка остановилась на этапе: CODE**, если оно есть.
3. Закройте и подтвердите терминал, нажмите «Проверить снова» и используйте
   текущее оставшееся действие, а не действие из прошлой попытки.
4. Если безопасного действия нет, обратитесь в
   [issues проекта](https://github.com/k-kostin/omavless/issues).
   Укажите действие, текст панели и код этапа, но не профили, ссылки или сырые логи.

<details>
<summary>Что означает код этапа</summary>

| Этап | Что не завершилось |
| --- | --- |
| runtime-directory / setup-lock / temporary-directory | Подготовка локальной транзакции. Оставшаяся блокировка не является автоматически удаляемым файлом. |
| private-initialization / store-validation | Подготовка или проверка приватных данных; данные не сбрасывались. |
| dns-enrollment / dns-broker-start | Административная операция; перед следующим действием проверьте завершённые шаги. |
| dns-broker-readiness / dns-socket-access | Не подтверждены необходимые факты службы или socket. |
| dns-template / dns-selection | Выбор управляемой конфигурации; пользовательские шаблоны не переписываются молча. |
| application-activation / runtime-enablement / completion | Не подтверждены активация, включение запуска или итоговая готовность. |
| upgrade-operation | Обновление отказало или не завершилось; перед продолжением проверьте фактически установленное состояние. |

</details>

Не удаляйте setup lock, запись ownership, журнал DNS или socket ради
продолжения. Переустановка не разрешает неизвестный исход и не даёт права
повторять возможно завершившуюся операцию. Используйте настройки → отчёт
поддержки → **Копировать отчёт / Сохранить файл**, а не сырые status/configuration.

<a id="updates"></a>

## Обновления

Обновляйте виджет и native-пакеты отдельно. Эта команда обновляет только виджет:

```sh
omarchy plugin update kdk.omavless
```

Версия 0.9.9 поставляет согласованные пакеты `omavless` и `omavless-dns`
для x86_64 и ARM64 с пакетной версией `0.9.9-1`. Используйте предложенное
обновление компонентов вместо смешивания отдельных загрузок. Одна строка
версии не доказывает, что файлы образуют поддерживаемую установку.

<a id="updating-the-public-082-application"></a>

### Обновление публичного приложения 0.8.2

Выключите автоподключение VPN при входе, отключитесь и полностью выключите
OmaVLESS. Обновите виджет, затем выполните `omarchy plugin enable kdk.omavless`,
чтобы открыть только виджет. Для поддерживаемой публичной установки 0.8.2
предлагается **Обновить OmaVLESS**. Оставьте приложение остановленным.
Подтвердите UPGRADE и обычные запросы sudo/pacman; настройка помощника и запуск
OmaVLESS следуют отдельными шагами. Неизвестная или изменённая установка
требует проверки, а не сброса данных.

<a id="already-using-098"></a>

<a id="updating-a-supported-public-098-installation"></a>

### Обновление поддерживаемой публичной установки 0.9.8

При частичной настройке сначала нажмите «Проверить снова» и выясните,
какой шаг остался. Не переустанавливайте пакеты лишь из-за отмены прошлого
терминала.

Когда предложено **Обновить компоненты…**:

1. Выключите автоподключение VPN при входе, отключитесь и подтвердите
   настройки → **Выключить OmaVLESS**.
2. Выполните `omarchy plugin enable kdk.omavless` и откройте только виджет.
   Оставьте приложение остановленным; перед обновлением не выбирайте
   «Запустить OmaVLESS».
3. Выберите «Обновить компоненты…». Подтвердите `PREPARE` и отдельный
   системный запрос прав. Это проверяет и при необходимости безопасно
   останавливает поддерживаемый помощник, но не устанавливает пакеты
   и не принуждает к остановке неизвестную операцию.
4. Тот же терминал затем запросит `UPGRADE`. Подтвердите его и обычную
   пакетную транзакцию. Enter отменяет до установки, оставляя старые пакеты
   и остановленный помощник. Затем закройте/подтвердите терминал и нажмите
   «Проверить снова». Следующее предложенное обновление заново проверит
   остановленное состояние, а не повторит завершённую остановку помощника.
5. После закрытия и подтверждения завершения выберите **Запустить
   DNS-помощник**, затем отдельно **Запустить OmaVLESS**, когда они предложены.
   Существующий доступ помощника не требует первоначальной выдачи прав.
   VPN автоматически не подключается.

Самый первый помощник исходной 0.9.8 не поддерживает автоматическую подготовку;
обратитесь за помощью для его защищённой замены. Изменённые, смешанные или
неизвестные установки нельзя принудительно проводить через обновление.
Не перезаписывайте пакетные файлы, не заменяйте один пакет отдельно
и не повторяйте выдачу DNS-доступа ради обхода отказа.

После успешного обновления может быть предложен необязательный `RELOAD`
всей Omarchy shell; Enter пропускает его. Другие плагины shell тоже
перезагрузятся. Ошибка reload не отменяет обновление и не разрешает повторять
его. При любом выборе запуск помощника и приложения остаётся отдельным действием.

<a id="verify-the-installation"></a>

## Проверка установки

Готовность означает наличие необходимых фактов приложения и компонентов,
но не доказывает доступ к серверу. Явно подключите нужный поддерживаемый
профиль, затем проверьте доступ к сайтам и учитывайте смысл Test/Ping,
описанный выше.

Если после замены виджета остались старые элементы управления или устаревшее
состояние, сначала завершите терминал и системные запросы, затем сознательно
перезагрузите shell:

```sh
omarchy restart shell
```

Это обновляет панель, окна и другие плагины, но не отдельный native runtime
VPN. Перезагрузка shell не восстанавливает незавершённую операцию runtime.

<a id="updates-close-quit-and-removal"></a>

## Обновления, закрытие, выход и удаление

| Действие | Эффект |
| --- | --- |
| Закрыть панель / терминал / перезапустить shell | VPN и принятые задания продолжают работать. |
| Отключиться | Останавливает VPN; приложение остаётся доступным. |
| Настройки → Выключить OmaVLESS / Quit | После подтверждения выключает приложение, выполняет очистку и останавливает/отключает запуск приложения и виджета; приватные данные сохраняются. |
| Постоянно отключить или удалить виджет | Запрашивает защищённое выключение приложения. Отсутствие значка не доказывает его завершение. |

Включите виджет заново, затем используйте предложенный шаг DNS и «Запустить
OmaVLESS». Новое VPN-соединение — отдельное действие. Автоподключение при входе
по умолчанию выключено. Если вы сознательно включили Last или закреплённый
профиль, настройка применяется при новом входе в систему; подтверждённое
отключение в текущем сеансе сохраняется при перезапуске приложения.
Запуск приложения при входе и подключение VPN — разные настройки.
После смены сети проверяйте текущее состояние и доступ вместо предположения,
что прежняя успешная проверка всё ещё применима.

<a id="reinstalling-the-widget-is-not-a-clean-app-installation"></a>

### Переустановка виджета не является чистой установкой приложения

`omarchy plugin remove kdk.omavless` удаляет виджет, но не native-пакеты,
доступ помощника или сохранённые профили. Повторное добавление продолжает
существующую установку. Используйте предложенное продолжение либо полное
удаление ниже.

<a id="remove"></a>

## Удаление

**Удаление стирает сохранённые профили и настройки OmaVLESS без резервной копии.**
Другие VPN-клиенты и отдельно установленный Mihomo остаются установленными.

Выберите **Удалить OmaVLESS…** в настройках или на экране настройки/ошибки.
Проверьте состав удаления и перейдите к его терминалу. Действие не требует
работающего соединения или завершённой первоначальной настройки. Если виджета
нет, добавьте текущий виджет командой установки выше и выберите удаление;
ради удаления не запускайте приложение и не подключайтесь.

1. Введите `REMOVE` для подтверждения удаления. Помощник при необходимости
   закрывает OmaVLESS и готовит удаление; пароль вводите только в запросе sudo.
2. Если нужна перезагрузка, сохраните другие работы и введите `REBOOT`
   либо перезагрузитесь позже через рабочий стол. Используйте продолжение
   без перезагрузки только тогда, когда оно предложено.
3. После нового входа продолжите **той же командой кэшированного помощника,
   которую напечатал этот терминал**. Сохраните её приватно; между этапами
   не скачивайте другой помощник и не открывайте/переустанавливайте приложение.
4. Подтвердите REMOVE и оставшиеся запросы пакетов/виджета.
   Дождитесь явного сообщения о завершённом удалении.

После отмены более ранний этап может уже быть выполнен. Сохраните прогресс
удаления и следуйте оставшемуся шагу; не удаляйте записи, не снимайте маски
служб и не очищайте сеть вручную. Неизвестные или изменённые сборки
и установки другой учётной записи отвергаются, а не угадываются.
После подтверждённого полного удаления новая установка снова требует
отдельного предложенного шага доступа помощника.

[Терминальная инструкция удаления 0.9.8](CLEAN_REINSTALL_098.md) относится
к той старой поставке; не используйте её старый checksum/помощник для другой
версии. Исторический `uninstall.sh --purge` не является native-командой удаления.

<a id="optional-helpers-firewall-and-older-installations"></a>

## Необязательные помощники, firewall и старые установки

Буфер обмена использует `wl-clipboard`; выбор файлов — zenity/kdialog/yad;
редактирование — zenity; показ QR — qrencode. Об отсутствии необязательного
помощника сообщается, он не устанавливается молча. Например, для намеренной
установки файлового диалога выполните `omarchy pkg add zenity`.
Для импорта из буфера файловый диалог не нужен.

Firewall с default-deny может блокировать туннельный трафик даже при
состоянии «Подключено». Настройка не выключает firewall и не меняет его правила.
Прочитайте [ограниченные указания по firewall](NATIVE_INSTALL_082_REFERENCE.md#default-deny-firewall-and-tun)
и проверьте фактический интерфейс, адрес и политику. Не копируйте исключение
для другого компьютера.

[Историческая инструкция 0.8.2](NATIVE_INSTALL_082_REFERENCE.md) описывает
старый stock-Mihomo и ручную миграцию. Это не текущий путь управляемой установки.

<a id="help"></a>

## Помощь

<a id="ask-your-assistant"></a>

### Обратиться к своему ассистенту

Откройте настройки → **Помощь** либо помощь по настройке. Выберите
**Скопировать запрос**, вставьте его в ассистента на этом компьютере
и опишите проблему в конце. **Показать запрос** позволяет проверить
и выделить текст при отказе копирования. Запрос не содержит профилей,
ключей или диагностических данных и указывает на установленную английскую
инструкцию для ассистента:

```text
Read the installed OmaVLESS assistance guide:
~/.config/omarchy/plugins/kdk.omavless/docs/user/USER_AGENT_GUIDE.md
Also read AGENTS.md in the plugin directory if present.

Help me with OmaVLESS in Omarchy. Problem:

```

[Инструкция для ассистента](USER_AGENT_GUIDE.md) объясняет безопасную
диагностику и проверку версий. Если виджет удалён, передайте это веб-руководство
и попросите ассистента сначала определить установленную версию.
Проверьте предлагаемое issue, исправление или обходной путь перед согласием
на публикацию. Использование ассистента или чтение руководства
не являются обязательными условиями для отправки сообщения о проблеме.

Помощь следует выбранному языку интерфейса, когда доступно соответствующее
проверенное руководство; иначе используется английский. Инструкции для
ассистента остаются английскими. Открытие ссылки само по себе не доказывает,
что браузер загрузил страницу.

<a id="setup-is-ready-but-websites-do-not-open"></a>

### Настройка готова, но сайты не открываются

Используйте рабочий поддерживаемый профиль и явно подключитесь.
Если сервер недоступен, попробуйте другой. Состояние «Подключено» и счётчики
сами по себе не доказывают доступ в Интернет, DNS или полную маршрутизацию.
Проверьте другие VPN и firewall, не выключая защитные проверки ради
сокрытия ошибки.

<a id="which-actions-leave-my-vpn-running"></a>

### Какие действия оставляют VPN работающим?

Закрытие панели, терминала и перезапуск shell оставляют его работать.
Напрямую — не отключение. Используйте отключение для соединения и
«Выключить OmaVLESS» для приложения. Удаление одного виджета
не является полным удалением.

<a id="do-i-need-to-install-or-configure-mihomo-separately"></a>

### Нужно ли отдельно устанавливать или настраивать Mihomo?

Нет. Согласованные ядро и DNS-помощник поставляются вместе в omavless-dns.
Не подменяйте их посторонним ядром или полной конфигурацией другого VPN-клиента.

<a id="why-does-pacman-still-show-098-1-after-an-update"></a>

<a id="how-do-i-check-which-components-were-updated"></a>

### Как проверить, какие компоненты обновились?

Используйте факты компонентов в панели и предложенное обновление.
Версия виджета не является версией native-пакета, а одинаковые пакетные версии
не доказывают одинаковые файлы. Неподтверждённое обновление требует проверки
перед новой попыткой.

<a id="can-i-restore-a-backup-or-remove-everything-from-settings"></a>

### Можно ли восстановить копию или удалить всё из настроек?

Терминальное приложение предлагает восстановление из копии с предпросмотром при безопасном
отключённом состоянии. «Удалить OmaVLESS…» открывает отдельную проверку
разрушительного удаления из настроек и экранов настройки/ошибки.
Ни одно действие не подразумевается удалением виджета.

<a id="how-do-i-ask-for-help-safely"></a>

### Как безопасно попросить помощь?

Используйте настройки → отчёт поддержки → «Копировать отчёт / Сохранить файл».
Укажите действие и короткую ошибку/этап. Перед публикацией проверьте скриншоты:
имена профилей и провайдеров, адреса подписок, секретные данные доступа, QR, резервные копии
и сырые приватные логи нельзя публиковать. О проблеме настройки можно сообщить
