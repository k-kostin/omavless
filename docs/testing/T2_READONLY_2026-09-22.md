## Defects caught and fixed before checkpoint

1. Forced terminal teardown could strand the event reader in backend polling.
   Six old synthetic fixture processes caused CPU load; repeated full-suite
   runs then hit timeout failures in unrelated existing process tests. Move
   terminal input off the UI/signal loop, bound its channel, stop the identified
   test processes, and repeat the complete suite. Final full run passed without
   changing production runtime logic or relaxing any test timeout.
2. Terminal restoration attempted to print an I/O error to a destroyed stderr;
   the default restore panic hook repeated restoration and aborted. Core-stack
   symbolization identified restore/panic-hook/Drop. Cleanup now uses fallible
   restoration without printing; the TUI-only error/panic path uses non-panicking
   fixed-message writes. The new real-PTY-teardown regression passes.
3. Unavailable metadata initially displayed a zero profile count; it now shows
   unknown. Search entry now explains Esc before q instead of advertising q as
   immediate close while it is being entered as text.
