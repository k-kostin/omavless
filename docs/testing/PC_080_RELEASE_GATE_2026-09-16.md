# Финальная x86-64 проверка готового OmaVLESS 0.8.0

Передача PC-агенту. Продолжи `k-kostin/omavless` на физическом Omarchy PC.
Пакет уже собран на x86-64 Arch: **не собирай Rust повторно**, если нет
подтверждённого изменения runtime или дефекта сборки. Этот prompt заменяет
план ручной сборки из передачи 15 сентября.

## Цель и границы

Проверить опубликованный кандидат: установка, правильная пара frontend/runtime,
открытие плагина, обычное подключение/отключение с существующим рабочим VLESS
профилем. Владелец планирует выполнить этот шаг позже 16 сентября. Дата — план,
не доказательство выполнения.

Не повторять весь R6, не начинать протоколы/TUI/AUTO-1. Не изменять реализации
#30/#135. Приватные имена, адреса, ссылки, пароли, UUID и ключи не выводить.
Пароль вводит человек в системном окне/sudo; нельзя автоматизировать `ready` /
`settled`, создавать повторные запросы или менять polkit ради проверки.

Владелец разрешил продвигать 0.8.0 к стабильному релизу и marketplace, но **эта
передача не означает, что последние gates уже прошли**. Не объявлять PASS по
одной сборке, версии пакета или включённому тумблеру. Никакого фиктивного
Connected. При реальном блокере сохранить данные и точную безопасную стадию.

## Перед установкой

Определить реальное состояние PC, а не предполагать, что оно совпадает с VM:
архитектура, установленный пакет, legacy/native ownership, startup/connection,
приватный store и рабочий профиль. Сохранить целиком приватные данные, текущий
frontend и известный рабочий пакет для восстановления. Только режимы/булевы
флаги/счётчики в публичном выводе.

Если уже подключено — согласованный обычный Disconnect, затем подтверждение
завершения авторизации. Проверить observed disconnected, recovery=false,
Mihomo/TUN=0. Startup Off для установки. Не удалять чужие данные/ядра и не
переустанавливать OS. Не ставить ARM-пакет на x86.

## Установка: выбрать фактическое состояние

1. **Приложение отсутствует:** обычный `omarchy plugin add` из репозитория,
   открыть Required components и пройти встроенную установку. Это публичный
   default-branch путь только после merge #249. Если #249 всё ещё Draft,
   установить clone disabled и выбрать точный reviewed B перед enable; честно
   записать подмену checkout, не называть её уже опубликованным main-flow.
   Подтвердить INSTALL / pacman / sudo и CORE только если действительно нужен
   Mihomo. Не передавать собственные URL в helper и не обходить зависимости.
2. **Native уже установлен:** guided helper намеренно не делает обновление
   активного владельца. Следовать existing-native package/frontend update из
   NATIVE_INSTALL: остановка с человеческими барьерами, `pacman -U` готового
   пакета, проверка байтов, соответствующий frontend, нормальный запуск.
   Не повторять activation и не править ownership-маркеры вручную.
3. **Legacy или повреждённое состояние:** применить документированный migration/
   recovery путь; не затирать store ради зелёного smoke. Если нет нужного
   архива восстановления или согласованной остановки, это реальный blocker.

Версия 0.8.0 сама по себе недостаточна: сверить ELF, unit files и frontend
с артефактами. Сервис должен запускать `/usr/bin/omavless`, не старый бинарник.

## Короткая фактическая приёмка

- Плагин enabled и открывается без QML errors; frontend соответствует B или
  доказанно byte-equivalent более позднему main. Язык/основной UI не сломаны.
- Если выполнялся first-run: отложить setup, переоткрыть, отсутствие приложения
  остаётся видимым; после установки/activation Required components исчезает;
  onboarding доступен; setup сам VPN не подключает. При уже установленном
  приложении не подменять этот сценарий ложным clean-install PASS.
- Существующий рабочий VLESS профиль: Connect → Full VPN с обычным человеческим
  подтверждением всех OS запросов; одна служба, один Mihomo/TUN, Unix controller
  отзывчив, TCP controller отсутствует. HTTPS-проба ограничена по времени.
- Disconnect → observed disconnected, recovery=false, Mihomo/TUN=0; режим и
  исходный профиль восстановлены, startup Off, plugin enabled.
- Не менять приватные имена ради отчёта; не создавать лишнюю подписку.

Отчёт: точные A/B/main/ELF/package hashes; OS/architecture/core version;
fresh или update path; onboarding/UI; connect/HTTPS/TUN/Unix-only/disconnect;
авторизация завершена или нет; исходное/конечное безопасное состояние; PASS/FAIL
по отдельным gates. Сохранить вывод, не raw logs и не screenshots с секретами.
