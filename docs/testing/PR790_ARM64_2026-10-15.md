## Earned results and defect

1. Executed the candidate guide's complete download/checksum/bootstrap block,
   selecting the immutable remote helper because public main lacks it.
   Anonymous download and exact SHA verification passed.
2. Enter cancellation before REMOVE: original exit **0**. Private config/state
   file hashes, installed packages/binaries, runtime PID, startup disabled and
   disconnected state stayed unchanged. Resolver JSON is equal after ignoring
   array ordering. No removal progress record was created.
3. Normal REMOVE from the running, disconnected public app: original exit **1**.
   Closing failed with a JSON parse error before confirmed shutdown. Runtime
   remained active, no package removal occurred, progress was `preparing`.
4. Read-only reproduction identifies the cause: the helper's `LC_ALL=C`
   causes Quickshell to prefix `omarchy plugin list --json` stdout with its
   non-UTF-8 locale warning. That command returns **0**, but output is not JSON.
   The same read-only query with `LC_ALL=C.UTF-8` returns valid JSON. This is
   a confirmed installed compatibility failure, not a successful Quit, and
   not evidence of broken VPN/DNS ownership. No candidate code was changed.
5. Same documented helper entry after that refusal: REMOVE uses its supported
   interrupted-preparation path, without resending Quit. It masks both user
   startup units, disables future DNS-broker boot activation, saves `prepared`,
   offers reboot, and exits **0** on restart-later. Existing idle runtime/broker
   remain alive until reboot; broker FD store is zero. Packages and private
   file hashes remain unchanged; direct HTTPS remains available.

Suggested owner-side correction: ensure the Quickshell JSON subprocess gets a
UTF-8 locale; do not strip arbitrary prefixes or weaken strict JSON validation.
Repeat affected installed shutdown acceptance on the corrected exact helper.
