## Source mechanism and relevance

[libproxy 0.5.12 config-env](https://github.com/libproxy/libproxy/blob/0.5.12/src/backend/plugins/config-env/config-env.c)
reads environment HTTP/HTTPS/FTP proxy variants and the bypass list, with this
plugin ordered first. This makes the child-environment strategy a genuinely
different input surface from the failed GNOME-settings consumer probe; it is
not repair of that probe. No all-proxy or HTTPS application coverage is inferred.

[GIO SocketClient](https://docs.gtk.org/gio/class.SocketClient.html) normally uses
the default resolver and enables protocol negotiation. The fixture leaves both
unchanged, connects to the synthetic HTTP target URI, and writes its bounded
HTTP GET through the returned GIO streams. The selected proxy and the actual
remote socket address must match the private owned listener; the response and
independent target receipt must match the fresh nonce.

[UWSM 0.26.7's application launch semantics](https://github.com/Vladimir-csp/uwsm/blob/v0.26.7/README.md#3-apps-and-slices)
distinguish default scopes inheriting parent environment from services using
manager activation environment. Passing this consumer gate proves neither
actual launch path. In particular, changing manager variables would not repair
an existing compositor/launcher parent or every new default-scope application.
Actual UWSM launch inheritance is a separate attended host gate after trusted
manager/broker/session admission and exact restoration are established.

preflight cannot stand in for it. Neither packet capture nor external/provider
network acceptance was run.
