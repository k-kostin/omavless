# T3 private composed developer artifacts

Additive opt-in on #575, exact base
`4239c4640d867f2a3629b9d8e378174c3921fb64`. This is developer build/export tooling,
not another runtime, installed package, distribution contract or close permit.
The existing default composition and its seven conditional / eleven DNS cases
remain unchanged. The [synthetic wire gate](T3_COMPOSED_DNS_WIRE_2026-10-03.md)
retains its own exact-head evidence.

`managed_composition.py --developer-export /absolute/private/new-directory`
requires both explicit Rust wire fixture identity arguments and `--udp-loopback`.
It runs the existing conditional/DNS matrices, all four wire scenarios twenty
times, the core TCP fixture and twenty UDP fixtures. Only after those succeed
does it build the actual DNS broker from an isolated object-only export of
`c4e800425243c1b02165f82153e4bf418fe465e6`, with the existing locked/offline
`--release --features release-package` recipe. The broker is **never executed**.
The feature name selects existing compiled paths; it grants no release status.

The new fixed-name bundle retains the tested core, actual built broker, Rust
channel fixture and Go wire test ELF; exact raw JSON matrix receipts and corpus;
production/test patches; core metadata and private broker build diagnostics;
and a bounded corresponding-source archive. Sources comprise the actual
patched/vendored core, sing-tun, exact c4 Rust source and exact committed clean
developer-builder source. Cargo output and temporary controllers/profiles are
not source-archive members. Original licenses remain inside each source tree.

The separate `omavless-composed-developer-artifacts-v1` manifest records source,
artifact, lockfile and observed toolchain hashes, architecture and build options.
Its `broker_executed`, `installed_compatibility`, `package_attestation` and
`effect_authority` fields are always false. The channel peer still uses an
ordinary regular-file proof and synthetic Ready/Released messages: recording
its receipt beside a broker does not establish broker execution compatibility.

## Publication and failure boundary

The caller provides an existing same-user 0700 parent outside the checkout;
all ancestors must be actual root/same-user directories without group/world
write. The destination must not exist. It is reserved exclusively as 0700;
fixed members are created exclusively, data 0600 and executables 0700, without
copying capabilities or extended attributes. Ancestors, destination and member
identities are checked; original member descriptors prevent inode reuse during
publication. The source archive copy uses one nonblocking/no-follow descriptor,
bounded reads, same-object metadata and exact output digest comparison.

Completion is written last only after every required member and all three
matrix receipts validate. Ordinary failure removes only names still identifying
objects this invocation created. Unexpected substituted objects are preserved
and cleanup refuses, rather than deleting another writer's replacement. A
SIGKILL/power loss may leave an incomplete reserved directory; no automatic
takeover or cleanup of an earlier invocation exists. This is cooperative private
developer tooling, not atomic protection against hostile same-UID mutation.

Compiler subprocesses have fixed offline environments, two Cargo build jobs,
bounded diagnostics/deadlines and owned-group cancellation before leader reap.
The wire execution supervisor remains separate from compilation so its smaller
file limit cannot restrict compiler/linker outputs. No running artifact is
rebuilt; exported executables live outside Cargo. Source/archive sizes are
bounded; no additional dependency, root helper or generic runtime IPC is added.

## Evidence and remaining gates

CPU tests use explicitly synthetic non-executable contents to exercise export
completion, partial failure, sync refusal, exact required members, existing
output refusal, private ancestry, member/directory replacement, symlink/FIFO
refusal and archive bounds. These tests do not prove compilation or wire effects.
Actual full-composition export and exact source/CI results are recorded on the
owning Draft PR after execution; they are not inferred from #575's earlier runs.

No normal ManagedPair, package stager/receipt schema, release pins, selector,
service, broker enrollment, private runtime state or conditional-close admission
changes. This bundle is deliberately incompatible with the normal release
receipt. Root-stated provenance, trusted issuance/distribution, both-architecture
build/acceptance, installed DNS/TUN lifecycle, normal permission and UI/IPC
adoption remain separate. No main/RC merge, installation, VM action, tag, release
or marketplace publication is authorized by this developer artifact.
