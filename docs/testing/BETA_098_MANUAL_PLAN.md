# 0.9.8: план ручной приёмки вместе с агентом

План, не результат теста. Кандидат: внутренняя `0.9.8-beta.3`, основанная на merge
`1a73f386ce0c78a9e5a7c4c5cedc2eec98bd6963` / проверенные исходники и пакеты
`06f9bc1ca416421948c0678e7c6b3ea3596368e7`, [#702](https://github.com/k-kostin/omavless/pull/702).
Новые источники: [#701](https://github.com/k-kostin/omavless/pull/701)
`ec7f5a9aa9fd35a5ae11216937d407ea83fd79ee` и
[#705](https://github.com/k-kostin/omavless/pull/705)
`d4f5ac2e3d644185a408dacc48dbd0b0a5bfd540`.
Агент записывает точный итоговый combined SHA и hashes реально установленного
пакета перед проверкой. Все пункты ниже **UNRUN на общей сборке**, пока явно
не записан их результат; программные gates нового кандидата проверяются отдельно.
[Правило внутренней beta](../development/BETA_MANUAL_ACCEPTANCE.md).

## Что действительно можно отдать на ручную проверку

| Направление | Статус в этой сборке |
| --- | --- |
| Обычный плагин/TUI, поиск, выбор, EN/RU, прокрутка, loading, режимы | Можно проверить через настоящий интерфейс после подготовки сборки; программные gates #702 пройдены |
| Закрытие отдельного соединения | Условно готово к ручной проверке: агент сначала готовит и подтверждает **совместимый close-qualified core/broker + Product helper/runtime** и dev-TUI; обычная пара пакетов этого не включает |
| Backup через TUI #705 + API #701 | Реальный экспериментальный экран; после программных gates и подготовки exact build можно передать на ручную проверку. Default TUI/Open app его не включают |
| Restore API #701 / новый preview `6164e7f5` | API есть в opt-in build, но Restore UI отсутствует; новый preview не включён. Вручную в интерфейсе пока не тестируем |
| Подписки по расписанию, sleep/network recovery, App proxy, kill switch | Не добавляются автоматически под ярлыком ручного теста; сначала закрываются их конкретные wiring/ownership/host gaps |

Этот список не навсегда замораживает состав beta. Следующая функция с готовым
пользовательским путём и пройденными программными проверками получает такую же
карточку и может войти с отметкой «ручная приёмка ожидается».

## Подготовка — делает агент

1. Получить ВМ от VM master; не управлять ею одновременно. Основной ПК не
   затрагивается. Отдельно согласовать, какие сетевые действия будем делать.
2. Проверить реальные source/package/frontend identities, совместимость и
   включённые возможности. Не объявлять dev-функцию доступной только по версии.
3. Подготовить безопасные тестовые профили A/B и нужные соединения, не публикуя
   ключи/адреса. Сохранить исходные данные; Restore никогда не проверять на
   единственной копии нужного приватного хранилища.
4. Зафиксировать начальный режим/соединение, источник наблюдения, допустимые
   поля, предел вывода/времени и состояние, в которое возвращаемся в конце.
   Использовать существующие semantic status/events и разрешённый ограниченный
   журнал; не запускать произвольный диагностический shell или новый observer.
5. Показать настоящий открытый экран. Перед каждым изменением сети назвать
   конкретный профиль/режим и ожидаемый эффект. Навигация не требует sudo.

## Блок A — без изменения соединения, около 5–10 минут

| Ты делаешь руками | Что ожидаем на экране | Что наблюдает агент / прямой вопрос |
| --- | --- | --- |
| Открываешь плагин, затем Open app; закрываешь только окно TUI и открываешь снова | Правильная версия, доступный интерфейс; закрытие окна не выключает VPN | Состояние одного runtime/desired остаётся прежним. «Соединение осталось включённым после закрытия окна?» |
| Выбираешь A для управления, когда подключён B; вводишь поиск, сворачиваешь/разворачиваешь группу, очищаешь поиск | Выбранный и подключённый профили различимы; кнопки действуют на указанный объект | Только наблюдение; revision/desired не меняются от выбора/поиска. «Какой профиль сейчас подключён и какой выбран?» |
| Tab/Shift+Tab, Escape, прокрутка, меньшее окно, EN/RU | Видимый фокус, доступные действия, без перекрытий/скачков; язык не меняет сеть | Снимки остаются приватными; агент сравнивает смысл и target. «Можно ли добраться до нижней кнопки клавиатурой?» |
| Открываешь Connections, rules/providers и возвращаешься назад | Пока данные читаются — loading, не ложное «недоступно»; stale/empty/unavailable различимы | Состояние соответствующего read-запроса/ответа; отсутствие новой мутации. «Было ли сообщение об ошибке до окончания загрузки?» |

## Блок B — обычные сетевые действия, около 5–10 минут

Только после отдельного согласования этого блока и известного рабочего профиля.
Чужие VPN/службы не останавливаются ради удобства наблюдения.

| Ты делаешь руками | Что ожидаем | Что наблюдает агент / прямой вопрос |
| --- | --- | --- |
| Один раз Connect на A, ждёшь завершения | Понятный переход; Connected только после подтверждения | Одна операция и её известный исход, совпадение desired/actual/target. «Была ли ложная красная ошибка во время ожидания?» |
| По очереди Routing → Full VPN → Direct, каждый следующий шаг только после завершения предыдущего | Выбранный/ожидаемый/подтверждённый режим различимы; нет ложной аварии | Исход каждого изменения и фактическая политика в пределах доступного observer. Открытый сайт не считается доказательством всех правил |
| Меняешь сервер A на B один раз | Видно переключение, после него отображается именно B | Смена target/core в допустимой наблюдаемой области; неоднозначность останавливает следующий шаг |
| Один раз Disconnect, затем проверяешь обычный доступ | Завершённое отключение, без оставшегося ложного Connected | Подтверждённый исход/owned cleanup только в пределах существующего наблюдения; возврат к согласованной исходной сети |

Не добавлять быстрые повторные клики для «лечения» unknown. Проверка обычных
переходов не закрывает fault injection, физический sleep/NIC или kill-switch.

## Блок C — закрытие конкретного соединения, после dev-подготовки

Агент заранее предоставляет реальное dev-окно, три безопасных потока A/B/C и
раздельное наблюдение их результатов. Человек не собирает helper и не вводит
сырые RPC/descriptor данные. Не выдавать обычный Open app за этот dev-режим.

1. В dev-TUI нажми `r`, выбери B по видимому назначению (`j/k` или стрелки),
   затем `x`. Проверь цель; нажми Escape. B и A должны продолжать работать.
   Вопрос агента: «После Escape B не закрылся и подтверждение исчезло?»
2. При необходимости **явно** получи новый список. Подготовь B через `x` и
   один раз подтверди Enter, пока подтверждение действительно. Истечение срока
   — отказ, не повод автоматически перепосылать действие.
3. При Pending нажми `u` только для чтения исходного receipt. Ожидаем Closed
   для B, A/C продолжают работать, VPN desired не изменился. Агент подтверждает
   результаты потоков и исход операции; одна надпись Closed недостаточна.
4. При Unknown не повторяй Confirm/Connect. Стоп и сохранение наблюдения.
   После известного завершения выйди `q`; следующее закрытие — отдельное явно
   открытое окно, не незаметное переиспользование старого контекста.
5. Проверить EN/RU и небольшой размер окна без новых сетевых действий.

## Блок D — настоящий экспериментальный Backup, около 5–10 минут

Агент готовит отдельный disposable store с известными тестовыми профилями,
подпиской и поддерживаемым routing template. Копируются только тестовые данные,
не основное приватное хранилище. Exact runtime собран с default `tui` плюс
`t4-manager-actor-service`; агент открывает `tui --developer-private-backup`
в реальном терминале. Наличие Settings Backup и текущей capability проверяется
до передачи пользователю. Обычный Open app остаётся без этого экрана.

Агент заранее фиксирует hashes/metadata пары, revision, Desired, history и
исходное состояние VPN; для архива — новый безопасный абсолютный путь не длиннее
160 UTF-8 байт. Человек вводит пароль длиной 12–1024 UTF-8 байта только в
маскированных полях, не в чат/argv/логи. Наблюдение ограничено исходным semantic
result/status и согласованным read-only сравнением тестовой пары/архива. Независимую
проверку расшифровки готовит агент; никакой Restore для этого не выполняется.

| Ты делаешь руками | Что ожидаем | Что наблюдает агент / прямой вопрос |
| --- | --- | --- |
| На основном экране нажимаешь `b` или `F2` для Backup, затем переходишь между полями Tab/Shift+Tab; EN/RU и окно 70×24 | Вход заметен в легенде и работает также из Activity/Settings; читаемые destination, маскированные два пароля и предупреждения; узкое окно не позволяет скрыто отправить запрос | Пока нет submit — нет файловой/VPN мутации. «Виден полный путь и понятно, что именно сохраняется?» |
| Вводишь разные пароли либо относительный путь и пытаешься перейти к подтверждению | Не появляется действительное подтверждение Create | Запрос не ушёл. «Получилось ли случайно отправить неверные поля?» |
| Вводишь корректные поля, открываешь подтверждение и нажимаешь Escape | Возврат без создания файла; секретные поля уничтожены | Исходная пара, revision и VPN неизменны. «После отмены пароль остался на экране?» |
| Снова заполняешь поля для нового пути, один раз подтверждаешь Create | Submitted → Completed только по достоверному исходному ответу; навигация не пересылает запрос | Один оригинальный запрос; архив аутентифицируется и соответствует объявленной тестовой паре, без изменения живой пары/revision/Desired/history |
| Отдельной новой операцией выбираешь уже созданный файл и подтверждаешь | Denied; существующий архив не перезаписан | Ciphertext hash и metadata неизменны. «Сообщение ясно говорит об отказе, а не об успешном сохранении?» |
| Закрываешь только TUI и открываешь снова обычный TUI/плагин | VPN не меняется; обычный клиент не выдаёт dev-функции за default | Один runtime, прежний Desired; личная настройка языка возвращена к исходной |

При Submitted/Unknown не повторять Create и не удалять файл: закрытие терминала
не отменяет backend-операцию. В рамках одной TUI-сессии уход/возврат не сбрасывает
неизвестный исход. Маскировка не обещает гарантированного стирания всех временных
JSON/terminal-library буферов. Backup сохраняет профили/подписки и конечный
поддерживаемый routing template, не все Settings, состояние ОС или runtime.
Owner-manual результаты этого блока пока **UNRUN**; агентский установленный
проход ниже имеет отдельный exact-head результат.

### Агентский установленный проход — отдельно от ручной приёмки

На exact `8de29a164e885f398dbb926c69fd377af4764869` в отдельной x86_64 ВМ
агент уже проверил настоящий EN/RU Backup TUI: пустой ввод, отмену и очистку
полей, одно создание с независимой аутентификацией точной пары и отказом
неверному паролю, затем отдельный отказ перезаписи существующего архива.
Исходные данные/metadata/history/revision и owned Off сохранились; закрытие
TUI не остановило runtime. Это не личная приёмка владельцем. Идентичности,
границы и найденная узкая UI-поправка сохранены в
[beta ledger](../development/BETA_098.md#beta3-installed-backup-checkpoint-2026-10-07).

Для короткой проверки владельцем агент открывает уже подготовленный экран
с синтетической парой. Достаточно проверить, что `b` заметен в Settings,
Tab/Shift+Tab и Escape понятны, предупреждения читаемы; затем при желании
выбрать **новый** путь и выполнить Create один раз. Агент заранее фиксирует
новый destination и наблюдает исход; ранее созданный файл не удаляется и не
перезаписывается. До этой личной проверки owner-manual результаты остаются
**UNRUN**, а не переименовываются в PASS по агентским действиям.

## Будущая карточка Restore — implementation pending

После появления проверенного экрана и включения соответствующего checkpoint:
агент готовит disposable store с известным A и копией, человек использует backup,
отменяет Restore без изменения данных, проверяет неверный пароль как отдельный
известный pre-effect отказ, затем один раз восстанавливает A из резервной копии
после намеренного изменения тестовых данных. Пароль вводится только в приватном
интерфейсе. Агент проверяет ровно объявленный состав восстановления, сохранность
не относящихся к нему данных, startup Off, завершённый исход и обычный restart.
Никакого обещания «восстановлено вообще всё» или simulated success. Пока реальный
UI/client путь не готов, эта карточка **implementation pending**, не manual-only.

## Стоп и фиксация результата

На неизвестном исходе, потере ownership, recovery-required, неожиданном запросе
ОС или расхождении цели — остановить зависимые мутации. Не повторять кнопку,
не удалять маркеры, не выключать чужие сервисы и не сбрасывать ВМ автоматически.
Агент определяет уже достигнутые эффекты и существующий безопасный следующий шаг.

Результат каждого блока: PASS / FAIL / UNRUN / INCONCLUSIVE, с точными
идентичностями и оговорками. Человек отвечает на конкретные вопросы; агент
прикладывает очищенные наблюдения, исправляет найденные дефекты и повторяет
затронутые проверки. План не является разрешением на main/release/Marketplace.
