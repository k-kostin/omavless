## Installed update and review

The VM began with the older `0.9.5beta1-1` application/DNS pair, committed Rust
ownership and an enabled plugin. The desired and observed state were
Disconnected/Rule, with no transition, recovery requirement or `Meta` TUN.
Before update, a private comparison of the profile and subscription lists was
recorded without exporting their contents.

The user runtime and root DNS broker were stopped inside the VM. The package
guard initially refused the broker's preserved socket, as designed. The root
broker was independently confirmed inactive/dead with PID and FD store zero;
its private directory was empty, the fixed socket was an unlistened root-owned
socket, and no TUN existed. Only that fixed transient socket was removed. The
unchanged guard then passed. Both version-matched archives were installed in
one normal `pacman -U` transaction, without force/overwrite/dependency bypass.
The matching frontend was installed with its native-only installer. The
existing ownership and plugin enabled state were preserved. The broker and
user runtime were started again without starting a VPN.

The installed `/usr/bin/omavless`, DNS broker and Mihomo hashes match the
inspected pair record. The installed frontend plugin files match the extracted
reviewed frontend. Native target remains `rust`. The installed CLI's bounded
status, capabilities, profile/subscription lists, plugin snapshot, runtime
observation and routing-rule reads returned successfully. The installed TUI
opened and closed with exit code zero; closing it did not stop the runtime.
Controller-dependent diagnostics returned `capability_unavailable` while
Disconnected; they were not counted as a connected diagnostic pass.

The Quickshell bar initially showed `STATE UNVERIFIED` after the frontend
replacement, even though fresh CLI observation reported healthy Disconnected.
The same shield state was visible in the VM before this update, so this does
not establish a 0.9.6 regression. Following the documented stale-frontend
remedy, restarting **only Quickshell** loaded the installed QML and the panel
then showed `DISCONNECTED`. The real panel was inspected in English at a
1890×2080 display resolution (scale 1.6667): its bounded subscription-arrow
tooltip and distinct no-match search message rendered; Escape cleared the
synthetic search. No Connect, mode change, subscription refresh or private
export was performed. Private captures remain outside Git.

The profile and subscription list fingerprints after update match the prior
ones; counts remain 37 and 1. Final VM state: desired/actual Disconnected,
Rule mode, no transition or manual recovery, no `Meta` TUN, plugin enabled,
one active user runtime and one active DNS broker. The panel and TUI were
closed. The physical PC was untouched.

## Boundary

This closes the **bounded installed x86_64 beta review** that the 0.9.6 beta
selection previously left open. It does not prove live VPN connectivity or
all selected UI states on x86_64, a fresh installation, anonymous/public
package download, bootstrap pins, or release acceptance. Public provisioning
and any later RC/owner-attended gates remain separate decisions.
