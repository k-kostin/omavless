## RC completion and publication boundary

Exact RC1 validation/artifacts and installed results are recorded in the owning
[RC PR #427](https://github.com/k-kostin/omavless/pull/427) before integration.
New packages never inherit beta archive hashes.

Engineering RC completion means frozen selected scope, green exact-source
checks, inspected matching architecture artifacts and the affected installed
ARM64 update/read-side gate. It does **not** authorize stable/main promotion.
Unchanged accepted DNS/lifecycle evidence is retained; new public-download,
fresh-account or owner-attended evidence is not inferred.

Public 0.9.5 assets/pins and fresh guided download verification need separate
release authorization. Empty package pins intentionally refuse public
provisioning. A later main proposal must reconcile candidate docs, release
notes/install instructions and limitations. Marketplace publication needs its
own explicit owner decision.
