## Ownership and effects

The same original actor performs canonical inventory, authentication, fixed-pair
staging, replacement and readback. Only a new closed canonical Commit request
selects this plan. It receives no pathname, generation, file descriptor or
serialized authority. Existing classic/default behavior is unchanged.

The fresh private developer transaction contains synthetic OLD live files,
immutable staged OLD/NEW/ready originals, Intent, and ultimately Committed.
The generation `1`, absent Desired record and nonce-derived transaction ID are
developer bindings, **not ProductOwner, singleton, installation or lease proof**.
The normal product's actual live pair is never selected.

Each NEW replacement is exclusively created at a fixed name in the fresh config
directory and immediately retained in the pre-reserved ReplacementStore or
ReplacementTemplate slot, before any post-call gate. There is no adoption of an
existing replacement, path-recapturing executor, FD export or descriptor cloning.
Both original OLD descriptors remain held after their intentional unlink.
Descriptor-relative rename changes which held original supplies a live name;
it does not evict the OLD original. Only the exact expected own rename may
advance link-count/ctime metadata; all other changes refuse.

Intent precedes either rename. Both replacements and the parent are synchronized,
and the held/name-bound live pair must equal exact staged NEW before Committed
is exclusively written. The existing DecisionRecord, StageIdentity and
LivePairClass rules determine the terminal/readback result. Final original
canonical refresh follows every file, catalogue and journal check. Only then
may the actor reply with the completed developer result and accept normal Halt.

Any error/late/unknown result seals the original owner, lower ledger, transfer
and channel. The uncertain actually reported prefix remains held by the same
live actor. No retry, automatic Abort, rollback, cleanup, reap or replacement
actor follows. Fatal actor loss means unavailable service, not preserved FD
custody. Unreported constructor internals remain outside this guarantee.
