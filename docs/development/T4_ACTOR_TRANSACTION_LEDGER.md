## Implemented lower primitives and their limits

The actor now retains its two complete comparison snapshots, including original
stat/status/cmdline/comm FD indices, alongside its reported original Files.
After crypto and before the authentication reply, `recheck_original` checks both
snapshots within the same actor borrow. It compares current descriptor-relative
PID/member/executable/namespace bindings, re-reads each original textual FD from
explicit offset zero, runs the original strict parsers and compares start,
credentials/namespace PID list, command/comm and executable link. No new open or
FD duplication occurs in this pass. The strict local two-second sampled budget
is clipped to the original operation deadline; failure seals that owner before
any further capture, reply or Halt. One fixed diagnostic literal follows the
completed check, with no raw PID/path/metadata output.

Linux v6.17 [seq_file producer](https://raw.githubusercontent.com/torvalds/linux/v6.17/fs/seq_file.c)
supports pread and resets its iterator when a request starts at offset zero.
That supports this original-FD refresh strategy; it is not a simultaneous global
snapshot or a claim about syscall preemption/kernel-buffer allocations. Proc
read errors, changes and late reads still refuse. Fixed PID1 remains the admitted
developer origin, not canonical user-manager/StoppedOwner/Restore authority.

`manager_actor_io.rs` reserves a fixed array of lower resource slots, provides
actual File open/openat adapters, and retains each reported return **before**
post-deadline or shape validation. Every Result failure permanently seals the
original ledger; later acquisitions/operations/Halt are unavailable. Existing
slot replacement is forbidden. Only a separately valid normal finish releases
the recorded prefix, under ordinary File-close semantics. No FD or reusable
proof is returned, no uncertain scratch slot is recycled, and fatal loss or an
unreported backend partial acquisition has no custody guarantee.

This adapter is compiled but not yet called by a wire operation. Its test
resources are memory Drop counters, not actual actor Files. Old stager,
journal, executor and private-directory helpers still contain caller-local
Files that can drop on Err. Merely wrapping their calls with this ledger would
not repair custody. Their new lower calls must each acquire through the ledger,
retain reported originals before checks and gate every continuation. A closure
is not permission to hide multiple ungated effects inside one outer check.
Read buffers/private outputs also need an owner before fallible post-checks.

Stage inspection now checks the **same exact five members** with a bounded
iterator, not collect/sort of an arbitrarily large directory. A positive result
