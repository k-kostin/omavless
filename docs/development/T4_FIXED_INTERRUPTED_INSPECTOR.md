# Fixed interrupted-transaction inspector

Inactive source successor of exact Commit `21c7ff72`, documentation base
`0947d554`. This is a read-only classification gate, not rollback, product
recovery, normal startup admission or continuity of the interrupted actor.

## One executable scenario

The closed developer scenario first runs the admitted canonical/Auth writer
through durable Intent, both owned replacements and the positive first rename.
It verifies its exact MIXED pair, immutable staged sources and original owner
before the declared `process::exit(86)` cut. This is controlled process-exit
interruption, not SIGKILL, power-cut or unknown-effect recovery evidence.

The original supervisor must observe without reaping through its retained
pidfd (`WNOWAIT`), classify exactly its original child's planned
86 and successfully reap that same expected exit, then permanently revoke that
original context. Any other/late/unknown result
stops before reaping: no fresh inspection launch, query, retry, compensation or cleanup. The
next actor has a new authenticated channel context/nonce and READY; it receives
only the bounded expected transaction ID, never the writer's Files, PID or live
proof. The same fixed listener may accept the distinct new connection; the old
stream/context cannot be reused. No arbitrary phase/path is caller-selected.

Before writer effects, the scenario reserves accounting for both actor/ledger/
channel owners. Each actual actor reserves its full lower ledger and private
input buffers before READY/acquisition. While alive the supervisor's fixed slots
hold its reported child/channel graph; there is no eviction/retry path. Parent
failure/return can close parent handles: this is not a joint supervisor/actor
graph-custody guarantee. The actor's refusal path separately parks its owned
lower/inventory/transfer prefix while alive; supervisor or actor loss means
unavailable, not fatal descriptor survival. The new scenario's explicit
whole budget must cover both phases; no failed-context deadline is restarted.

## Read-only owning boundary

The fresh inspector independently captures `/run`'s fixed developer transaction
hierarchy, both current live files, four staged OLD/NEW members, ready, Intent,
optional terminal and optional fixed replacement files. Every positive File is
retained in the same pre-reserved lower ledger before its postchecks. It uses
its own current canonical manager/namespace/inventory proof and fresh fixed
archive authentication. It does not adopt an old descriptor or reconnect a lost
actor. Earlier stopped experiments are never inputs to this scenario.

Exact bounded staged bytes and ready must match the authenticated fixed pair.
Intent must match expected transaction ID, developer generation `1`, absent
Desired and the actual StageIdentity. Optional absence is checked under the
original directory and repeated by whole fixed catalogues; it is not a no-FD
or no-resource proof. Exact held/name metadata, bytes, hierarchy and catalogues
are repeated before the final original whole refresh. No sync, write, rename,
unlink, signal or recovery operation belongs to inspection.

The existing DecisionChain rules classify Intent/OLD, MIXED, NEW or IDENTICAL as
only `OldRollbackCandidate`; NEW alone never proves commit. Committed requires
NEW/IDENTICAL; Aborted requires OLD/IDENTICAL. Crossed/torn/foreign/divergent or
unknown evidence refuses or reports manual recovery. The result is historical
classification, never a live mutation capability. Only a positively completed
fresh inspection may accept its own normal Halt.
